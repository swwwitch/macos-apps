SiteMirror 会跟踪您输入的 URL 所在网站的页面，并保存 HTML、CSS、JavaScript、图像和字体。保存的文件中的链接会改写为相对路径，因此即使没有网络连接，也能在浏览器中打开查看。

## 使用方法
### 下载网站
1. 在“URL：”中输入要下载的网站 URL（例如 https://example.com/）。可以省略“https://”。也可以将浏览器地址栏中的 URL 或链接拖放到窗口中。
2. 点按“保存到：”旁的“更改…”选择保存文件夹。默认是“下载”文件夹。
3. 点按“下载”（Return 或 ⌘R）。列表中会显示已保存的文件及其保存位置，以及失败或排除的 URL 和原因。
4. 完成后，点按“在浏览器中打开”打开起始页面，或点按“在访达中显示”显示保存的文件夹。
- 会在下载文件夹中创建“SiteMirror-log.txt”，以制表符分隔记录日期时间、数量以及失败和排除的 URL、原因和引用来源（链接到该 URL 的文件）。可点按“打开记录”打开。覆盖下载时会替换该文件。
- 在列表上方选择“失败”或“已排除”，只显示未能保存的 URL 及原因。选择行后按 ⌘C，或右键点按并选择“拷贝 URL”“拷贝 URL 和原因”即可拷贝（选择多行时按行分隔）。已保存的行可通过右键菜单中的“在访达中显示”显示该文件。

### 需要登录的网站
1. 输入 URL 后点按“登录…”，该网站会在应用内的浏览器中打开。
2. 照常登录后点按“完成”。已登录的网站会在按钮图标上显示勾号。
3. 点按“下载”时会使用该登录状态（Cookie）。对于要求输入名称和密码的网站（Basic 认证），也会使用该名称和密码（直到退出 SiteMirror）。
- 登录期间，不会跟踪 URL 中包含 logout、sign-out 等的页面（跟踪会导致退出登录）。
- 登录状态保留在应用内的浏览器中。可在“登录…”窗口中点按“清除登录信息…”清除所有网站的登录信息。

### 检查失效链接
- “检查链接”（⇧⌘R）会跟踪与下载相同范围的页面，但不保存任何内容，只确认链接目标是否存在。指向其他网站的链接也会确认是否存在，但不跟踪。
- 结果会以“<主机名>-linkcheck-<日期时间>.txt”写入保存文件夹，可通过“打开记录”打开。其中列出失效的 URL、原因和引用来源页面。

### 跟踪范围
- 跟踪与起始 URL 相同主机的页面。有无“www.”以及 http 与 https 的区别视为同一网站。如果起始 URL 被重定向，重定向目标的主机也视为同一网站。
- 页面显示所需的文件（CSS、JavaScript、图像、字体、视频等）即使位于其他域名（如 CDN）也会保存。可以在设置的“下载”中关闭。不会跟踪其他域名的页面。
- 如果同一网站的链接指向 PDF 或 ZIP 等文件，也会保存该文件。
- 默认不跟踪被 robots.txt 排除的页面。

### 保存的文件夹
- 在保存文件夹中创建以网站主机名命名的文件夹（例如 example.com）。
- 如果已有同一网站的文件夹（包括将该文件夹本身选为保存位置时），会询问“覆盖”“保存到新文件夹”或“取消”。覆盖时会用本次下载的文件替换，未更改的图像等只向服务器确认而不重新下载（为此会保留“.sitemirror.json”列表）；本次未下载的旧文件会保留。“保存到新文件夹”会保存到带编号的文件夹（如“example.com 2”）。
- 中途停止的下载，再次下载到同一文件夹时可以选择“继续下载”。已保存的文件不会重新下载，只下载剩余部分。
- 在设置中打开“将网站上已不存在的文件移到废纸篓”后，覆盖下载完整结束时，会将上次保存但本次已无链接指向的文件以及服务器返回 404/410 的文件移到废纸篓，并在记录文件中列出。
- 网站的文件按原来的路径结构放在该文件夹下。其他域名的文件放在“_hosts/<主机名>”中。
- 没有扩展名的页面（如“/about”）保存为“about.html”，以文件夹结尾的页面（如“/blog/”）保存为“blog/index.html”。带有“?id=1”等查询的 URL 会在文件名中加上简短标记，保存为单独的文件。

### 改写链接
- 下载完成后，会将已保存的 HTML 和 CSS 中的链接改写为指向已保存文件的相对路径。
- 指向未保存文件（其他网站的页面、失败的文件等）的链接会改为原来的绝对 URL。
- 会移除 <base> 标签。为避免改写后的 CSS 无法载入，也会移除 integrity 和 crossorigin 属性。
- 即使中途停止，也会改写已保存文件中的链接。

## 设置
点按主窗口中的“设置”按钮（⌘,）打开。
- **启动与后台**：登录时启动、不在程序坞和应用程序切换器中显示、在菜单栏中显示。打开“不在程序坞和应用程序切换器中显示”后，程序坞和 ⌘Tab 切换中不显示图标。可通过菜单栏图标（显示时）或在访达中再次打开应用来显示窗口
- **下载**：是否保存其他域名的文件、是否跟踪子域名的页面、是否不跟踪起始 URL 所在文件夹以上的页面、是否遵循 robots.txt、包含的 URL（设置后只跟踪匹配的页面）、排除的 URL（每行一个，例如 ?page=、/tag/）、是否跟踪 sitemap.xml 中的页面、是否提取 JavaScript 中的 URL（推测）；跳过的文件类型（扩展名，例如 mp4, zip）、单个文件上限、总上限（MB）；链接深度（默认无限制）、文件数上限（默认 10,000）；同时连接数（默认 4）、请求间隔（默认无）、失败时重试（默认 2 次，仅限超时和临时错误）；覆盖时是否不重新下载未更改的图像等（默认打开，HTML 和 CSS 每次都重新下载）、是否将网站上已不存在的文件移到废纸篓（默认关闭）。更改从下一次下载开始生效。
- **设置共享**：导出和导入“下载”设置，并通过 iCloud 云盘、Dropbox 等文件夹与其他 Mac 同步。保存文件夹在每台 Mac 上分别设置。
- **关于**：版本和链接。

## 快捷键
- **Return / ⌘R**：下载
- **⇧⌘R**：检查链接
- **⌘.**：停止
- **⌘0**：打开主窗口
- **⌘,**：设置
- **⌘W**：关闭窗口
- **⌘?**：SiteMirror 帮助
- **⌘Q**：退出 SiteMirror

## 权限与隐私
- 不需要辅助功能权限。
- 仅连接您输入的网站以及其页面所载入文件所在的位置（“检查更新…”除外）。会发送表明是 SiteMirror 的 User-Agent。仅向通过“登录…”登录的网站发送其 Cookie 和认证信息。登录状态保留在应用内浏览器的存储位置（~/Library/WebKit 中）。
- 如果选择“下载”等文件夹作为保存位置，macOS 可能会请求访问许可。
- 请按照网站的使用条款和著作权使用下载的内容。同时连接数过多会给对方服务器带来负担。

## 启动与退出
- 关闭窗口不会退出应用。点按程序坞图标或按 ⌘0 可再次显示主窗口。
- 打开“在菜单栏中显示”后，也可以从菜单栏图标选择“打开主窗口”“设置…”和“帮助”。
- 要退出，请从应用菜单选择“退出 SiteMirror”（⌘Q）。下载过程中会先确认；选择停止后，会为已保存的文件改写链接后再退出。
- 可通过应用菜单中的“检查更新…”检查新版本。在更新分发准备就绪之前，会显示正在准备，且不进行通信。

## 疑难解答
- 由 JavaScript 稍后载入的图像和页面无法保存。会跟踪写在 HTML 和 CSS 中的链接。在设置中打开“同时提取 JavaScript 中写的 URL”后，可能会提取 JavaScript 中写的图像等 URL。
- 如果在浏览器中打开时显示错乱，可能是浏览器限制了从本地文件载入。在保存的文件夹中运行“python3 -m http.server”等简单服务器后再打开，可能会正常显示。
- 如果看起来中途停止，可能已达到文件数上限，或对方服务器没有响应。请查看列表中失败的原因。
- 如果持续出现“HTTP 403”等失败，说明网站拒绝自动下载。请减少同时连接数、设置请求间隔或停止下载。
- 如果登录后仍出现“HTTP 401”“HTTP 403”，请通过“登录…”重新登录。登录可能已过期。

## 帮助与 note 文章
- 可通过“帮助”菜单中的“SiteMirror 帮助”（⌘?）打开本帮助。
- “帮助”菜单中的“打开 note 文章”会在浏览器中打开 note 上的介绍文章。

## 删除应用
1. 关闭“登录时启动”。
2. 选择“退出 SiteMirror”。
3. 将 SiteMirror 移到废纸篓。下载的网站文件夹会保留在保存位置。

手动启动或重新打开应用时显示主窗口。登录时自动启动不显示主窗口。明确打开文件时优先执行该操作。
