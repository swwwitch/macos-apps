# KageTrimmer

macOSのスクリーンショットなどの画像に付いている影をコンパクトに整えたり、影のない画像に影を追加したりして、PNGで保存するネイティブアプリです。macOS 14以降／Apple Silicon用です。

## 使い方

1. 影の大きさ（影なし／XS／S／L）と「薄い罫線を付ける」を選びます。起動時の影の大きさは設定の「出力」タブで選べます（初期値はS）。
2. 画像をウインドウにドロップするか、「画像を選択…」（⌘O）で読み込みます。Finderの「このアプリケーションで開く」やDockのアイコンへのドロップでも処理できます。
3. 元画像は変更せず、同じフォルダに `元の名前-接尾辞.png` を書き出します。接尾辞は影の大きさで決まります（影なし `-no-shadow`、XS `-xs`、S `-s`、L `-l`）。設定の「出力」タブで影の大きさごとに変更でき、空欄にするとデフォルトに戻ります。同じ名前のファイルがある場合は置き換えず、`名前-s 2.png` のように番号を付けて保存します。

設定の「設定の共有」タブで、影の大きさ・罫線・接尾辞・処理に成功したときの動作を `KageTrimmer-Settings.plist` に書き出し・読み込みしたり、iCloud Drive・Dropboxなどのフォルダーで複数のMacと同期したりできます（ログイン時の起動・メニューバー・ホットキー・フォルダ監視はMacごと）。

設定の「フォルダ監視」タブをオンにすると、監視するフォルダ（初期値はmacOSのスクリーンショットの保存先）に追加されたウインドウのスクリーンショットを、メインウインドウで選んでいる影の大きさで自動的に処理します。

ファイルを渡して起動した場合は処理後に終了し、起動中のアプリへファイルを渡した場合は処理後も起動したままです。ログイン時に起動したときはメインウインドウを表示しません。

## ビルド

```sh
zsh build.sh
```

`build/KageTrimmer.app` を生成します。スクリプトは `Shared/BuildTools/publish_latest.py` で `Latest Builds/KageTrimmer.app` にも配置します（`APP_STORE_BUILD=1` のときは配置しません）。署名は証明書（PL9S9PXX96、`KAGETRIMMER_SIGNING_IDENTITY` で変更可）で行います。バージョンとbuildは `Info.plist` だけで管理し、`KageTrimmer.xcodeproj` の `MARKETING_VERSION`／`CURRENT_PROJECT_VERSION` も同じ値にそろえます。

画像処理の確認は `Sources/ShadowProcessor.swift`、`Sources/Localization.swift` と `Tests/ProcessorSmoke.swift` を一緒に `swiftc -parse-as-library` でコンパイルし、引数に一時ディレクトリを渡して実行します。テストはそのディレクトリだけを操作します。

### 1.2.2（build 62、2026-10-14）

- 角丸から直線に移るあたりで、窓の縁の画素が1つ抜ける（ドット欠け）問題を修正した。横と下に同じ距離の不透明な画素があると外向きの方向を辺に沿った向きと誤り、窓の内側の白を影として差し引いていた。
  - 影の濃さは「窓から2px以上離れた純粋な影の画素のうち、3px以内で最も濃いもの」で見積もるようにした。辺に沿って滑らかに変わるので、角と直線の境目で輪郭の濃さが段になることもない。

### 1.2.1（build 61、2026-10-14）

- 影のある画像の角丸がきれいに仕上がらない問題を修正した。これまでは窓の周り2pxの半透明部分を残して3×3でぼかしていたため、窓の細い暗い輪郭に白が混ざって消え、角の階段や古い影の灰色の帯が見えていた。
  - 縁の画素は「黒い影の上に窓を重ねたもの」なので、外側2画素から影の不透明度を推定して差し引き、窓だけの不透明度に戻すようにした（乗算済みの色はそのまま）。ぼかしはやめ、不透明な画素は1バイトも変えない。
  - 外側の影を測れるよう、窓の範囲より4px広く切り抜いてから処理し、最後に窓の範囲へ切り詰める。

### 1.2.0（build 60、2026-10-14）

- 設定に「フォルダ監視」タブを追加した。オンにすると、監視するフォルダにウインドウのスクリーンショットが追加されたとき、メインウインドウで選んでいる影の大きさで自動的に処理する（初期値はオフ）。ウインドウは表示せず、処理が終わると効果音（Glass）を鳴らす。
  - 監視するフォルダの初期値は macOS のスクリーンショットの保存先（`com.apple.screencapture` の `location`、なければデスクトップ）。［選択…］で変更できる。App Store 版はフォルダを選ぶとセキュリティスコープ付きブックマークで保存する（`files.bookmarks.app-scope` を追加）。
  - ウインドウの判定：macOS 標準のスクリーンショットは拡張属性 `kMDItemScreenCaptureType` が `window` のものだけ（範囲指定 `selection`・画面全体 `display` は処理しない）。拡張属性のない画像は、EXIF の UserComment が `Screenshot`（CleanShot X なども書く）で、透明な影の余白か透明な四隅（影なしで撮ったウインドウ）があるものをウインドウとみなす。CleanShot X で背景（壁紙・単色）を付けて撮ったウインドウは不透明なので判定できない。ヘルプと設定に、CleanShot X の背景を「透明」・保存先を監視するフォルダにする案内を載せた。処理後の `-s.png` などはこの情報を持たないので、再処理されない。
  - 隠しファイル（macOS が書き込み中の `.Screenshot…`）は無視し、サイズが2回続けて同じになってから読む。
