# 高速化 第1段階（2026-10-25）

対象：通常版・Lite。配布済み版は変更せず、ソースと検証ビルドのみ。

## 変更

- selectSidebarは同じカテゴリなら何も変更しない。検索文字・フォント選択を保持し、一覧更新番号を進めない。
- sidebar/searchTextへの同値代入はキャッシュ無効化を省く。空の検索文字・空の選択にも不要な再代入をしない。
- FamilyNodeCacheを導入し、既存listVersionが同じ間は親行と子行の配列を共有。検索、カテゴリ、ライブラリ、アクティブ状態などによるlistVersion更新時は再生成する。
- 保存形式・設定キー・検索照合・ソート・NSOutlineViewの展開／スクロール復元処理は変更しない。

## 計測

最適化コンパイル（swiftc -O）。合成フォントデータ（1ファミリー4ファイル）で実際のFamilyNode生成処理を100回呼ぶ場合と、同じ版のキャッシュを100回読む場合を比較。初回生成時間、検索、実ファイル読み込み、画面描画は計測に含まない。1回の観測値であり、アプリ全体の高速化率ではない。

| 版 | ファイル数 | 従来の100回生成 | キャッシュ後の100回参照 |
| --- | ---: | ---: | ---: |
| 通常 | 8,000 | 135.617 ms | 0.007 ms |
| 通常 | 40,000 | 640.390 ms | 0.034 ms |
| Lite | 8,000 | 133.465 ms | 0.009 ms |
| Lite | 40,000 | 702.276 ms | 0.038 ms |

両版の実際のselectSidebar・sidebar/searchText宣言を抽出したテストで、同じカテゴリの1,000回選択に対して一覧更新番号の増加0、検索とフォント選択の保持を確認。別カテゴリの通常選択では検索をクリアし、Option相当の指定では保持。空検索での移動では一覧更新1回。

## 検証方法

- `python3 NotMyType/Tests/check-sidebar-performance.py`
- `FamilyNodeCacheTests.swift`を各版のFontLibrary.swift、FontWeightOrder.swift、Localization.swift、FamilyNodeCache.swiftとswiftc -Oでコンパイル。通常版のみFontDB.swiftも含める。SmartSetの最小スタブは単独コンパイル用で、スマートセット条件の評価はこのテストの対象外。
- 行ID・順序・子行の一致、配列ストレージの再利用、版変更時のメタデータ更新・空配列への変更・並び替えを検証。
- 日英ローカライズ検査。
- 両版のarm64/x86_64 release検証ビルド。配布用.appの生成・配置・起動は行わない。

## 未確認・今後

実画面の応答時間と展開・スクロール状態の回帰確認は、次回の配布ビルドで実施。初回の一覧生成や検索そのものを短縮する変更は未実装。検索用文字列の事前準備、状態変更時の更新範囲縮小、プレビュー計算の再利用は今回の対象外。
