HotkeyHound는 키 조합을 어떤 앱이 설정했는지 찾아 주는 앱입니다. 단축키가 작동하지 않을 때 어디서 가로채는지 찾는 데 사용합니다.

## 사용 방법
### 키로 찾기
1. “클릭한 뒤 키를 누르세요”를 클릭하고 찾을 조합을 누릅니다(파일 > 키 찾기 ⌘K로도 시작할 수 있습니다).
2. 누른 키는 다른 앱에 전달하지 않으므로 찾는 동안 매크로 등이 실행되지 않습니다. 보조 키 없이 Esc를 누르면 취소합니다.
3. 그 키를 설정한 출처가 목록에 표시됩니다. 활성인 것이 2개 이상이면 경고 표시가 붙습니다.

### 확인 범위
- 위쪽 전환으로 “모든 앱”과 “앱 지정”을 선택합니다.
- “앱 지정”에서는 오른쪽 팝업 메뉴에서 선택한 앱의 메뉴와 그 앱에서 작동하는 단축키(모든 앱용, 그 앱 대상)만 확인합니다. 다른 앱 전용은 표시하지 않습니다.
- 전환하면 직전에 사용하던 앱이 선택됩니다. 실행 중이 아닌 앱은 “기타…”에서 선택할 수 있습니다(메뉴는 확인하지 않음).

### 표시 보는 법
- **비활성**: 출처의 설정에서 꺼져 있습니다(매크로나 그룹 비활성화, 규칙 끄기 등).
- **실행 안 됨**: 단축키를 제공하는 앱(Keyboard Maestro Engine 등)이 실행 중이 아니어서 지금은 작동하지 않습니다.
- 결과 오른쪽 위의 “비활성 단축키 숨기기”를 켜면 비활성·실행 안 됨 항목을 숨깁니다.
- **보조 키를 더해도 반응**: Karabiner-Elements 규칙으로, 다른 보조 키를 더해도 반응합니다.
- 행을 Control-클릭하면 내용 복사와 출처 앱 열기를 선택할 수 있습니다.

## 찾는 출처
- **macOS 단축키**: 시스템 설정 > 키보드 > 키보드 단축키(Spotlight, Mission Control, 입력 소스 등).
- **서비스**: 서비스에 지정한 단축키.
- **앱 단축키(시스템 설정)**: 시스템 설정에서 메뉴 항목에 지정한 단축키.
- **실행 중인 앱의 메뉴**: 실행 중인 앱의 메뉴 막대에 있는 단축키. 그 앱이 앞에 있을 때만 작동합니다.
- **Keyboard Maestro**: 매크로 단축키와 그룹 활성화·팔레트 단축키. 대상 앱도 표시합니다.
- **BetterTouchTool**: 키보드 트리거. 메모·폴더·프리셋·대상 앱을 표시합니다.
- **Karabiner-Elements**: 선택한 프로필의 규칙과 키 바꾸기. 바뀌는 결과도 표시합니다.
- **Alfred**: Alfred를 표시하는 단축키, 클립보드 기록 등 기능의 단축키, 워크플로 단축키. 관련 앱도 표시합니다.
- **Default Folder X**: 파일 대화상자·Finder·전체 단축키.
- **Keystroke Pro**: 키 표시를 켜고 끄는 단축키.
- **ATOK**: 사용 중인 스타일의 키 설정(ATOK Customizer의 키 사용자 설정). ATOK가 켜져 있을 때만 작동하므로 적용 상태(입력 없음·입력 중·변환 중 등)도 표시합니다.
- **Adobe Illustrator**: Illustrator에서 선택한 키보드 단축키 세트. 사용자 세트는 해당 .kys 파일을, 기본 세트는 내장된 기본값을 읽습니다. 도구 키(V·A 등)는 기본 키로 표시합니다.
- **자작 앱(swwwitch)**: CommandDee·MightyEdit·FolderHopper 등이 기록한 단축키(~/Library/Application Support/swwwitch/Hotkeys). 작동 범위와 앱 실행 여부도 표시합니다.
- **KeyboardShortcuts 형식 앱**: KeyboardShortcuts 라이브러리로 단축키를 저장하는 앱(DemoPro 등). 이름은 설정의 식별자입니다.
- **사용자 출처**: 설정 파일을 읽을 수 없는 앱의 단축키를 설정의 “출처”에서 직접 입력해 등록한 것.

### 찾지 못했을 때
- “시스템(또는 다른 앱)이 이 키를 독점하고 있습니다”가 표시되면 macOS 단축키 등이 독점 등록한 것입니다.
- “키 입력을 가로챌 수 있는 앱”에는 키 입력을 받는 장치(이벤트 탭)를 가진 앱을 나열합니다. 설정을 읽을 수 없는 앱이 원인이라면 이 앱들을 하나씩 종료하며 시험해 보세요.
- 다른 앱이 공유 방식(예: RegisterEventHotKey)으로 등록한 단축키는 macOS에 목록을 가져오는 방법이 없어 찾을 수 없습니다.

## 설정
메인 윈도우의 “설정” 버튼(⌘,)으로 엽니다.
- **시작 및 백그라운드**: 로그인 시 열기, 시작할 때 메인 윈도우 가리기, Dock 및 앱 전환기에 표시 안 함(Dock과 ⌘Tab 전환기에 아이콘을 표시하지 않음. 메뉴 막대 아이콘 또는 Finder에서 앱을 다시 열어 표시), 메뉴 막대에 표시, 손쉬운 사용 권한 상태
- **출처**: 출처별 켜기/끄기와 드래그로 순서 변경(결과도 이 순서로 표시), 각 출처의 개수. “출처 추가…”로 사용자 출처를 만들어 키·이름·적용 범위를 등록할 수 있습니다(연필로 편집, 휴지통으로 삭제).
- **설정 공유**: 선택한 출처, 출처 순서, 사용자 출처와 “비활성 단축키 숨기기”를 파일로 내보내 다른 Mac에서 가져올 수 있습니다(‘추가’는 아직 없는 사용자 출처만 더하고, ‘대치’는 파일의 설정으로 바꿉니다). iCloud Drive나 Dropbox 등의 폴더를 동기화 폴더로 설정하면 여러 Mac을 자동으로 맞춥니다. 로그인 시 열기, 시작 시 윈도우, 메뉴 막대, 확인할 앱은 Mac마다 남습니다.

## 단축키
- **⌘K**: 키 찾기
- **⌘R**: 다시 읽기
- **⌘0**: 메인 윈도우 열기
- **⌘,**: 설정
- **⌘W**: 윈도우 닫기
- **⌘?**: HotkeyHound 도움말
- **⌘Q**: HotkeyHound 종료

## 접근 권한
- 손쉬운 사용 권한을 사용합니다. 누른 키를 다른 앱보다 먼저 받고, 실행 중인 앱의 메뉴를 읽기 위해서입니다.
- 권한이 없어도 쓸 수 있지만, 다른 앱이 먼저 받는 키는 기록할 수 없고 메뉴는 확인하지 않습니다.
- “시작 및 백그라운드”의 “손쉬운 사용 설정 열기”에서 허용합니다.
- 다른 앱의 설정 파일은 읽기만 하고 바꾸지 않습니다. 통신도 하지 않습니다.

## 열기와 종료
- 윈도우를 닫아도 앱은 종료되지 않습니다. Dock 아이콘을 클릭하거나 ⌘0을 누르면 메인 윈도우를 다시 표시합니다.
- “메뉴 막대에 표시”를 켜면 메뉴 막대 아이콘에서도 “메인 윈도우 열기”, “설정…”, “도움말”을 선택할 수 있습니다.
- 종료하려면 앱 메뉴에서 “HotkeyHound 종료”(⌘Q)를 선택합니다.
- 앱 메뉴의 “업데이트 확인…”으로 새 버전을 확인할 수 있습니다. 배포 준비가 끝날 때까지는 준비 중으로 표시하고 통신하지 않습니다.

## 문제 해결
- 눌러도 기록되지 않으면 손쉬운 사용 권한을 확인하세요. 허용 후에도 반영되지 않으면 앱을 다시 시작합니다.
- Karabiner-Elements는 키를 바꾼 뒤의 결과가 이 앱에 전달되므로, 바뀐 키로 표시될 수 있습니다.
- 설정을 바꾼 직후 결과가 오래된 경우 “다시 읽기”(⌘R)를 누르세요.
- 메뉴가 많은 앱은 읽는 데 몇 초 걸릴 수 있습니다.

## 도움말과 note 글
- 이 도움말은 도움말 메뉴의 “HotkeyHound 도움말”(⌘?)로 엽니다.
- 도움말 메뉴의 “note 글 열기”로 note의 해설 글을 브라우저에서 엽니다.

## 앱 삭제
1. “로그인 시 열기”를 끕니다.
2. “HotkeyHound 종료”를 선택합니다.
3. HotkeyHound를 휴지통으로 옮깁니다.
4. 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용에서 HotkeyHound를 삭제합니다.

수동으로 실행하거나 다시 열면 메인 윈도우를 표시합니다. 로그인 시 자동 실행에서는 표시하지 않습니다. 파일을 명시적으로 열면 해당 작업을 우선합니다.
