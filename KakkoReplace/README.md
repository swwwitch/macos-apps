# KakkoReplace

macOS 13以降 / Apple Silicon。0.3.19 (build 39)。選択した文字列のカッコを挿入・置換するメニューバーアプリです。

## 起動と使い方

`/Applications/KakkoReplace.app` を起動します。アクセシビリティの許可が必要です。既存の許可が反映されない場合は、現在の配置先のアプリをシステム設定で確認してください。

- 記事の26ホットキーを初期設定にしました。全角丸括弧は⌘⇧9、半角丸括弧は⌘⌥⇧0です。
- メニューバーの「カッコのパレット」または⌥⇧⌘Uでパレットを開きます。対象アプリの入力欄へ戻り、文字を選択してボタンを押してください。
- 設定の「ホットキー」→「操作」で、種類別のキーを記録・解除できます。記事のキーを一度だけ適用して以前の割り当てを設定内へバックアップします。その後の変更・解除は保持します。重複登録を防止し、OS登録失敗は該当操作に表示します。
- 初期値へのリセットは選択中の操作だけが対象です。全体の無効化・一時停止・対象外のアプリの設定は維持します。

## 対応する操作

| 分類 | 種類 |
| --- | --- |
| 日本語の括弧 | （） ［］ 【】 〈〉 《》 「」 ｛｝ 『』 |
| 引用符 | “” ‘’、半角の二重引用符と一重引用符 |
| 半角括弧 | () [] {} <> |
| コメント | HTML `<!-- -->`、CSS `/* */` |
| 整理 | 外側のカッコを削除、すべてのカッコを削除、前後にスペース |

選択がなければ一組を挿入し、内側へカーソルを移します。選択内に括弧がなければ囲み、中の元文字列を選択します。括弧があれば選択内の最外層だけ置換し、処理後の範囲全体を選択します。複数組はまとめて置換し、内側の入れ子は保持します。片側だけ・左右の種類が違う括弧にも対応します。

例えば `（外「内」）` を【】にすると `【外「内」】`、外側削除では `外「内」`、すべて削除では `外内` になります。`”文字“` のように選択両端が逆向きの引用符も補正します。単語中のアポストロフィは括弧として扱いません。

「既存のカッコを置換せず、外側に追加する」をオンにすると強制的に囲みます。HTML/CSSコメントは常に囲む動作です。コメント構文の解析・削除は対象外です。

「置換するカッコの前後の半角スペースを削除」は初期オフです。オンなら選択範囲内で置換する括弧に隣接する半角スペースを除去します。新しく囲む場合は選択の両端の半角スペースを除去します。改行・タブ・全角スペースは保持します。強制追加とスペース処理の設定は全種類で共通です。

参考：[DTP Transitの記事](https://note.com/dtp_tranist/n/n0dd769786d9b) の公開本文・パレット画像。添付マクロの内部実装は参照していません。記事の「カーソルを末尾へ移動」「元文をクリップボードに残す」ではなく、本アプリで先に指定された選択保持とクリップボード不使用を維持しています。

## 対応範囲と復元

標準アクセシビリティAPIで文字と選択範囲を読み書きできる入力欄が対象です。非対応・読み取り専用・パスワード欄では実行しません。IME変換を確定してから使用してください。書式の保持は対象アプリに依存します。Illustratorなど独自の入力欄は非対応の場合があります。

コード構文を解析しないため、HTMLタグや数式の `< >` も括弧として扱います。操作したい範囲だけ選択してください。クリップボードを使わず、編集後に文字と選択位置を読み戻します。「直前の変更を復元」は原入力欄の内容が編集直後と一致するときだけ最後の1回を復元します。復元情報はメモリのみで、終了時に破棄されます。

## 常駐・設定

「起動・常駐」→「ウインドウを閉じても常駐」は初期オンで、設定を保存します。オフなら最後のウインドウを閉じた時に終了します。ログイン起動のオン／オフとは独立しています。ログイン起動時は画面を開きません。既存のログイン起動の選択、対象外のアプリ、ホットキー無効化を維持します。

4言語のオフラインヘルプ、マスタード基調のアイコン、共通の更新機能（Shared/Updater、Sparkle。配信先と署名鍵が未設定の間は準備中と表示し通信しない）を同梱。外部通信・本文ログなし。

メニューバーの（）は共通部品MenuBarPresenceで管理します。アプリメニューの「メニューバー設定…」または設定の「メニューバーに表示」で表示を切り替えられます（初期値は表示）。非表示でもアプリは終了しません。

## ビルドと配置

`./build.sh` でビルド、`./test.sh` で検証します。Xcode Command Line ToolsとPython 3を使用。既存ビルドはBackupsへ退避します。生成済み.appをソースとして編集しません。

既定は開発用ad-hoc署名です。`SUPERKAKKOREPLACE_SIGNING_IDENTITY`（旧`SUPERKAKKOEDIT_SIGNING_IDENTITY`も互換対応）で署名IDを指定できます。再ビルドや移動でアクセシビリティの再許可が必要になる場合があります。Developer ID署名・公証・自動更新は未設定です。

最終版：`/Applications/KakkoReplace.app` および `Latest Builds/KakkoReplace.app`。Bundle ID/設定保存先は旧名の `jp.local.SuperKakkoEdit` を維持します。旧版と旧アイコンはBackupsに保存しています。

## パレットの対象と可変列（0.3.0 / build 18、2026-10-07）

パレットを呼び出したときの前面アプリを対象として保持し、別アプリが前面になったらパレットを隠します。別アプリで再び呼び出すと、そのアプリが対象になります。環境設定からの呼び出しでは直前の外部アプリへ戻ります。対象アプリを確認できない場合は表示しません。アプリ切り替えを挟んだ修飾キー解放待ちの編集はキャンセルし、パレットからの復元も現在の対象アプリに限定します。

ボタンは幅を固定し、ウインドウを広げると列数を増やします。括弧・引用符は72pt、コメントは110pt、その他の操作は220pt。高さ44ptと間隔8ptを維持します。

検証：ビルド、既存の変換・起動・ショートカット試験、4言語84キー検査に合格。実際のAppKitグリッドを幅250→330→490→250ptへ変更し、括弧ボタンが72×44ptのまま3→4→6→3列となることを検証しました。両配置先の署名と全ファイル一致を確認し、/Applicationsから再起動したプロセスを確認。GUI接続エラーのため、実画面でのアプリ切り替え・呼び出し・編集操作は未確認です。

## ショートカットの発火を MightyEdit 方式に（0.3.17 / build 37、2026-10-10）

- キーを押した時点で実行するようにした（MightyEdit の performOnPress と同じ）。これまでは修飾キーがすべて離れるのを最大2秒待ち、間に合わないと取り消していたため、押し続けると発火しないことがあった。編集はアクセシビリティ経由なので、押したままの修飾キーは対象アプリに影響しない。
- 同じキーを押し続けても1回だけ実行（キーを離すまで、または10秒経つまで次を受け付けない）。
- アプリを切り替えるたびに全ショートカットを登録し直すのをやめ、有効・無効や割り当てが変わったときだけ登録し直すようにした（切り替え直後に取りこぼす隙間をなくす）。

## 設定のタブにずれたフォーカス枠が出る不具合を修正（0.3.18 / build 38、2026-10-10）

- 設定ウインドウを開くと、選択中のタブにずれた青いフォーカス枠が出ていた。タブ（NSTabView）にフォーカス枠を描かないようにした（共通部品 SettingsSection.swift）。

## アクセシビリティ欄の空白と見出しの重複を修正（0.3.19 / build 39、2026-10-10）

- 「起動・常駐」のアクセシビリティ欄の下に空白が出ていた。部品が高さを180pt固定で申告していたのを、中身の高さで申告するようにした（共通部品 Shared/Accessibility/AccessibilityPermission.swift）。
- セクション名と部品の見出しで「アクセシビリティ」が二重に出ていたので、部品側の見出しを出さないようにした（showsTitle: false）。
