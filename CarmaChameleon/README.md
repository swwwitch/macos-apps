# CarmaChameleon（旧名 PandocDesk）

SwiftUI/AppKitによるpandocの非公式ネイティブGUI。Apple Silicon / macOS 13以降。

入力ファイル・出力形式・変換オプションの3カラム。原本保持、連番による上書き回避、非同期変換、取消、部分成功の表示。pandoc 3.12を同梱。PDFは環境設定からTypstを導入可能。既存のXeLaTeX／LuaLaTeXも利用可能。

環境設定でpandocの有無、使用バージョン、パス、最新版との比較を表示。公式GitHub release APIによる明示的な確認、公式SHA-256検証後のユーザー領域インストール、同梱版への復帰を用意。確認前や通信失敗を「最新版」とは表示しない。独自の実行ファイルパスは自分が信頼するpandocのみを指定する。

ビルド: `./build.sh`。共通部品は `../Shared/AppStandards/` を直接使用。LoginAtLaunchとLaunchPolicyはFolderMoverのローカライズ済み実装を再利用。

ライセンス: 同梱pandocはGPL-2.0-or-later。Resources内のCOPYINGとTHIRD-PARTY-NOTICESを参照。対応する上流ソースもSourceArchiveとして同梱。GUIソースもGPL-2.0-or-laterで提供する。

サポート: この開発フォルダのREADMEおよびBASELINE-CHECKLIST。公開問い合わせ先は未設定。
アプリの配信更新・Developer ID署名・公証は未設定。ローカル用ad-hoc署名。診断ログは保存しない。

## 0.10.0 / build 35

- 出力形式に「ファイル名のみ」を追加（カテゴリに入れず、一覧の一番上・「ビジネス」の上に表示）（Source/FileNameConverter.swift）。内容はそのままで、Mac と Windows の両方で使える名前を付けたコピーを作る。どの種類のファイルでも追加できる（ほかの形式が読めないファイルは「ファイル名のみ」だけに変換できる）。
- Windows で使えない記号（\ / : * ? " < > |）は「全角にする」（初期値）か「_ に変更」。制御文字・先頭の空白・末尾の空白とピリオドを取り除き、CON・PRN・AUX・NUL・COM1〜9・LPT1〜9 には「_」を付ける（「con.txt」→「con_.txt」）。
- 「スペース」は「そのまま」（初期値）・「_ に変更」・「- に変更」。全角スペースも対象。
- 「Unicode正規化（NFC）」（初期値オン）。macOS で分かれて保存されたかなの濁点・半濁点、ハングル、アクセント付きの文字を1文字にする。CJK 互換漢字（神 U+FA19 など）は macOS と同じく置き換えない。
- 名前を変える必要がなく保存先が元と同じフォルダーのときはコピーせず、結果に表示する。同名は連番で回避。設定は保持。
- 設定の「変換形式」をメインウインドウと同じカテゴリ（見出し）ごとに表示。並べ替えはカテゴリの中で行う。
- OpenDocument と LaTeX を初期状態で非表示にした（以前の版の設定にも一度だけ適用。「初期状態に戻す」でも非表示）。

検証：自動テストで、記号の全角化と「_」化、NFC（かな・ハングル・アクセント）と互換漢字の保持、正規化オフ、制御文字と前後の空白・ピリオドの削除、スペースの3通り、予約名、未対応の種類のファイルのコピーと原本保持、変更不要時のスキップ、別フォルダーへのコピー、入力の判定が成功。画面からの操作は未確認。

## 0.11.0 / build 36

「ファイル名のみ」のオプションを追加。

- 「処理」：「コピーを作成」（初期値）か「元のファイルの名前を変更」。改名ではその場で名前を変え、入力ファイルのリストも新しい名前にする（保存先の設定は使わず、画面にもそう表示）。
- フォルダーに対応。中のファイル・フォルダーもまとめて変換する（コピーでは原本を残し、改名では中から順に変更）。.DS_Store と「._」で始まるファイル（Finder のデータ）は変えない。フォルダーは「ファイル名のみ」でだけ選べ、追加・「ファイルを選択…」でも受け付ける（「ファイル名のみ」を表示しているとき）。
- 「機種依存文字・絵文字を置き換える」（初期値オフ）：①→(1)、㈱→(株)、Ⅰ→I、㍉→ミリ（CP932 の NEC 特殊文字・IBM 拡張の記号を NFKC で）、〜→～・−→－・‖→∥・—→―・¢£¬→全角（Windows の CP932 の形）、絵文字は取り除く。髙・﨑などの IBM 拡張の漢字は名前なので変えない。
- 「名前を［100］文字までにする」（初期値オフ、10〜255）。拡張子を残し、文字の途中（絵文字・濁点）で切らない。短くした件数と、フォルダーの中のパスが200文字を超えたときは結果に表示。
- 「先頭の「.」」：「そのまま」（初期値）・「_ に変更」・「取り除く」。
- `"` の全角を ＂（U+FF02、CP932 では IBM 拡張）から ” に変更。
- 修正：Swift の文字列比較は NFD と NFC を同じとみなすため、濁点が分かれているだけの名前を「変更不要」と判定していた。コードポイントで比較するようにした。
- 修正：FileManager や Data.write はファイル名を NFD に分解して書くため、NFC にした名前が元に戻っていた。最終的な名前は renamex_np（RENAME_EXCL、上書きしない）で付ける。正規化だけが異なる改名は、APFS が同じ名前とみなして綴りを変えないため、一時名を経由する。

検証：自動テストで、機種依存文字・Windows の形・絵文字、先頭の「.」の3通り、長さの制限（拡張子と文字の保持）、NFD の名前のコピー（ディスク上で NFC）とその場の改名、フォルダーのコピー（原本保持・中の名前・Finder のデータ）とその場の改名、フォルダーの入力判定、フォルダー内の短縮と長いパスの表示が成功。画面からの操作は未確認。
